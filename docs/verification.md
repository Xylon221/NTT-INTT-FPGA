# 验证与结果解释

## 验证层次

1. **数学约定。** Python 检查长度、模数、单位根阶和逆元。小规模变换使用直接求和核对，负循环乘法使用 `O(N²)` 朴素卷积核对。仅验证 `INTT(NTT(a))=a` 不足以证明变换定义正确。
2. **模块。** 模乘检查零、单位元、接近模数的值与随机值；验证连续事务和流水复位。蝶形核对两路输出与有效信号配对。TFG 核对递推序列、组首复位及有效信号握手。
3. **完整变换。** 同一输入向量分别运行 ROM 和 TFG 版本，核对正/逆、循环/负循环变换。对每次运算比较全部输出系数，错误信息应包含模式、索引、期望值、实际值。
4. **多项式乘法。** 依次执行两个负循环正变换、RTL 逐点模乘和一个负循环逆变换，并比较全部输出。小规模用独立朴素卷积交叉验证；大规模使用确定性种子向量验证。
5. **性能。** 仅在正确性比较通过后汇总 ROM/TFG 的内部周期数和因子存储口径。仿真超时、编译失败和系数不一致均应使运行返回非零状态。

测试向量、随机种子、参数和生成命令应一并保留。修改参数、算术器件或控制调度后，应重新生成向量和执行上述检查。

## 周期口径

核内周期从核心接受 `start` 到完成运算计数，不含输入加载、输出读取、Python 启动、Verilog 编译和仿真器运行开销。ROM/TFG 应使用相同 `N/q/W`、相同操作和输入，以报告中的实际计数计算：

报告的 `pointwise` 行单独由测试平台计量，从逐点乘任务启动至最后一个流水输出，包含首次发射前的等待拍，共 `N+3` 拍；它不经过核心 `start/done` 接口。

```
cycle_increase_percent = (cycles_tfg / cycles_rom - 1) * 100
```

如需换算实际时间，必须使用在目标器件上已经验证的工作频率，不能把约束频率或 PC 仿真速度当作硬件频率。

## 存储口径

默认唯一幂表 ROM 为每个方向 `N/2` 个 `W` 位值，两方向合计 `N*W` 位。TFG 对比应说明计入哪些级常量和运行状态；系数 RAM、公共参数和预/反扭转状态应分别列出或明确共同排除。比例计算为：

```
storage_reduction_percent = (1 - tfg_factor_bits / rom_factor_bits) * 100
```

不能将“每蝶形重复存一份因子”的表与“唯一幂共享 ROM”的表混为同一个基线。也不能只计算一个 TFG 寄存器而忽略步长常量，却把 ROM 两方向全部计入。

## Vivado 综合入口

先生成与 `LOG_N` 匹配的 ROM 初始化文件，再在已配置 Vivado 的 Linux shell 中运行。例如，使用真实器件料号替换 `YOUR_FPGA_PART`：

```bash
cd /home/xylon/projects/ckks-ntt-fpga
PART=YOUR_FPGA_PART LOG_N=13 USE_TFG=1 vivado -mode batch -source fpga/synth.tcl
PART=YOUR_FPGA_PART LOG_N=13 USE_TFG=0 vivado -mode batch -source fpga/synth.tcl
```

脚本在未设置 `PART` 时拒绝运行，避免把示例器件当成真实目标。ROM 模式同时检查向量元数据的长度、模数、原根和幂表项数，防止误用其他配置的初始化文件。两种模式应使用同一器件、工具版本和约束。报告默认写到 `build/synth_tfg` 或 `build/synth_rom`；可用环境变量 `OUT_DIR` 指定独立目录。

默认 `fpga/constraints.xdc` 仅提供 10 ns 的核心时钟目标，没有开发板管脚、电气标准、完整 I/O 延迟或板级时钟资源约束。低有效同步复位保持为需要约束的输入路径。`report_utilization` 与综合后时序报告只用于初步评估；最终结论需补充布局布线、完整约束和板级验证。
